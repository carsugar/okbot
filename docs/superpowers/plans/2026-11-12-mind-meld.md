# Mind Meld Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/mindmeld` Discord game where two players privately enter words each round and the bot reveals both at once until they match.

**Architecture:** Pure game rules live in `src/mindmeldRules.js` (testable in plain node). A Durable Object (one per game) loads state, calls the rules, saves state. Discord handlers in `src/mindmeld.js` turn command/button/modal interactions into DO calls and Discord responses. The last submitter's modal response is the public reveal, so no bot-token posting is needed.

**Tech Stack:** Cloudflare Workers + Durable Objects (SQLite-backed), `discord-interactions`, `itty-router` (existing), `wink-lemmatizer` (new), `node:test` for tests (built in, no new dependency).

**Spec:** `docs/superpowers/specs/2026-11-12-mind-meld-design.md`. One deviation: the spec put `applyWord` in `src/mindmeld.js`. It is split into `src/mindmeldRules.js` because `mindmeld.js` imports `cloudflare:workers` and cannot load under node.

## Global Constraints

- Words: trimmed, lowercased, single word (no whitespace), at most 32 characters.
- Match = any noun/verb/adjective lemma of one word equals any lemma of the other (`wink-lemmatizer`). No stemmer.
- The reveal shows words as typed; a match reached only through lemmatizing says so.
- Locked-in words cannot be changed. No round cap, no give-up. 24h idle expiry via DO alarm.
- Partner can't be yourself or a bot. `/mindmeld` is open to everyone (no `default_member_permissions`).
- No `!important`, no `as any`; JS repo with no tsconfig, so `tsc` does not apply.
- Existing tag-template code is not modified.

## Review Focus

- A player clicks Submit twice in one round: second word is rejected, first stays. (Task 1 test)
- Empty, multi-word, or 33+ character input: rejected, nothing stored. (Task 1 test)
- A third user clicks Submit or submits a modal: refused, state unchanged. (Task 1 test)
- Submit after the game is won, or after the 24h expiry: friendly message, no state change. (Task 1 test for won; Task 2 handles expired)
- Identical starting words, or `Rain ` vs `rain`: immediate match. (Task 1 test)

### Task 1: Game rules (pure)

**Files:**
- Create: `src/mindmeldRules.js`
- Test: `test/mindmeldRules.test.js`
- Modify: `package.json` (add `wink-lemmatizer` dependency, `"test": "node --test"` script)

**Interfaces:**
- Produces:
  - `normalizeWord(raw: string): string | null` (null when empty, contains whitespace, or longer than 32)
  - `wordsMatch(a: string, b: string): boolean` (expects normalized input)
  - `newGame(players: [string, string], now: number): GameState`
  - `submitWord(state: GameState, userId: string, rawWord: string, now: number): { state: GameState, result: SubmitResult }`
  - `GameState = { players: [string, string], pending: Record<string, string>, history: Array<Record<string, string>>, status: 'active' | 'won', updatedAt: number }`
  - `SubmitResult` is one of: `{ type: 'invalid' }`, `{ type: 'not_player' }`, `{ type: 'finished' }`, `{ type: 'already_submitted' }`, `{ type: 'waiting' }`, `{ type: 'revealed', round: number, words: Record<string, string>, matched: boolean, exact: boolean }`. `round` is 1-based. `history` is only appended on reveal; `status` becomes `'won'` when matched; `pending` is cleared on reveal. `pending` and `history` store each word trimmed but with its original case (for display); `normalizeWord` is applied only for validation and the match check.

- [ ] **Step 1: Install dependency and add the test script**

Run: `npm install wink-lemmatizer` then add `"test": "node --test"` to `package.json` scripts.

- [ ] **Step 2: Write failing tests in `test/mindmeldRules.test.js`** (import from `../src/mindmeldRules.js`, use `node:test` + `node:assert/strict`)

  - `normalizeWord`: `' Rain '` → `'rain'`; `''`, `'   '`, `'two words'`, `'a'.repeat(33)` → `null`; `'a'.repeat(32)` is valid.
  - `wordsMatch`: true for rain/raining, mouse/mice, leaf/leaves, run/ran, cat/cats; false for universe/university, happy/happiness, rain/train, desert/dessert.
  - `submitWord`: first word `' Rain '` → `waiting` and stored in `pending` as `'Rain'`; second word from other player with non-matching word → `revealed` with `matched: false`, `round: 1`, history length 1, pending empty, status `active`; same-user second submit in a round → `already_submitted` and `pending` unchanged; outsider → `not_player`; `'two words'` → `invalid`; submit when status `won` → `finished` with state unchanged; matching words (`'Rain'` vs `'rain'`) → `matched: true, exact: true`, status `won`; `rain` vs `raining` → `matched: true, exact: false`; a second round after a non-match works and reports `round: 2`; `updatedAt` equals the `now` passed on accepted submits.

- [ ] **Step 3: Run `npm test`**. Expected: FAIL (module not found).

- [ ] **Step 4: Implement `src/mindmeldRules.js`** with the signatures above. Lemma set for a word = `{ lem.noun(w), lem.verb(w), lem.adjective(w) }` (`import lem from 'wink-lemmatizer'`); match when the sets intersect. `submitWord` is non-mutating (returns a new state).

- [ ] **Step 5: Run `npm test`**. Expected: all PASS.

### Task 2: Durable Object and Discord handlers

**Files:**
- Create: `src/mindmeld.js`
- Modify: `wrangler.toml`

**Interfaces:**
- Consumes: Task 1's `newGame`, `submitWord`, `GameState`, `SubmitResult`; `JsonResponse` from `src/utils.js`.
- Produces:
  - `MINDMELD_COMMAND` (command object: name `mindmeld`, option `partner`, type 6 USER, required)
  - `class MindMeldGame extends DurableObject` (`import { DurableObject } from 'cloudflare:workers'`) with RPC methods `start(players: [string, string]): Promise<void>`, `check(userId: string): Promise<'ok' | 'not_player' | 'finished' | 'expired'>`, `submit(userId: string, word: string): Promise<SubmitResult | { type: 'expired' }>`
  - `handleMindMeldCommand(interaction, env): Promise<JsonResponse>`
  - `handleMindMeldComponent(interaction, env): Promise<JsonResponse>`
  - `handleMindMeldModal(interaction, env): Promise<JsonResponse>`
- Custom ids: button `mm:submit:<gameId>`, modal `mm_modal:<gameId>` with one short text input `word`. `gameId` is the command interaction id; DO is `env.MIND_MELD.get(env.MIND_MELD.idFromName(gameId))`.

- [ ] **Step 1: `wrangler.toml`**: add binding `MIND_MELD` → class `MindMeldGame`, and migration `tag = "v1"`, `new_sqlite_classes = ["MindMeldGame"]`.

- [ ] **Step 2: Implement `MindMeldGame`.** State under storage key `state`. Every accepted `start`/`submit` calls `ctx.storage.setAlarm(now + 24h)`; `alarm()` calls `ctx.storage.deleteAll()`. Missing state means `expired`. `check` returns `'finished'` when status is `won`.

- [ ] **Step 3: Implement `handleMindMeldCommand`.** Reject (ephemeral, flags 64) when the partner equals the invoker or `interaction.data.resolved.users[partnerId].bot` is true. Otherwise `start([invokerId, partnerId])`, then reply public (type 4) with a lobby message mentioning both players, explaining the game in two lines, and one **Submit word** button (style 1, custom id above). Invoker id is `interaction.member.user.id`.

- [ ] **Step 4: Implement `handleMindMeldComponent`.** Call `check`; for `not_player`, `finished`, `expired` reply ephemeral with a short message each (not your game / game is over / game expired, start a new one). For `ok`, reply type 9 modal titled `Mind Meld` with one required short text field (`custom_id: 'word'`, label `Your word`, `max_length: 32`).

- [ ] **Step 5: Implement `handleMindMeldModal`.** Read the `word` field (see `getField` in `src/tagTemplates.js` for the component layout), call `submit`. Reply by result type:
  - `invalid`: ephemeral "One word only, up to 32 characters."
  - `already_submitted`: ephemeral "You already locked in a word this round."
  - `not_player`, `finished`, `expired`: same ephemeral messages as Step 4.
  - `waiting`: ephemeral "Locked in. Waiting for your partner."
  - `revealed`, not matched: public message with `allowed_mentions: { parse: [] }`: round number, both words as typed next to each player's mention, a line "Next: a word that connects **x** and **y**." (the two just-revealed words), the full history of earlier rounds, the line "Think a pair should have matched? Tell the organizers.", and a fresh **Submit word** button.
  - `revealed`, matched: public message with the chain of all rounds, "Mind meld!", and no button. When `exact` is false, add that the words counted as a match (e.g. "rain / raining").

- [ ] **Step 6: Syntax check**: `node --check src/mindmeld.js` is not possible with the `cloudflare:workers` import, so run `npx wrangler deploy --dry-run` and expect a successful bundle.

- [ ] **Step 7: Commit** (`src/mindmeld.js`, `wrangler.toml`).
